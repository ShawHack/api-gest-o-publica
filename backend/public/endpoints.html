Documentação da API SEMIT

Documentação completa da API REST da SEMIT – Secretaria de Inovação e Tecnologia da Prefeitura de Garça. Inclui endpoints para Memorial Santa Faustina (sepultados), Pets, Árvores, Formulários, Denúncias e demais módulos. Todos os endpoints estão organizados com exemplos de requisição e resposta.

🔐 Autenticação: A API aceita dois métodos — JWT (Bearer Token) no header Authorization ou API Key no header X-API-Key. Para integrações automatizadas, use API Key. Veja a seção API Key – Gerar e usar.

🌐 Acesso Externo (API Key)

Para integrações entre sistemas (machine-to-machine), use API Key em vez de login de usuário. Permite acesso autenticado sem gerenciar tokens JWT.

1. Como gerar uma chave segura

Execute no terminal (Node.js instalado):

node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

Exemplo de saída: a1b2c3d4e5f6789012345678901234567890abcdef1234567890abcdef123456

Guarde a chave gerada – ela não será exibida novamente.

2. Como configurar no servidor

No arquivo .env do backend, adicione:

# Chaves válidas (separadas por vírgula para múltiplas chaves)
API_KEYS=sua_chave_gerada_aqui,outra_chave_parceiro

# Opcional: vincular a um usuário (para operações que precisam de userId)
# API_KEY_USER_ID=64f1234567890abcdef

Reinicie o servidor após alterar o .env.

3. Como utilizar nas requisições

Envie a chave no header X-API-Key em cada requisição:

HeaderValor
X-API-KeySua chave gerada (ex: a1b2c3d4e5f6...)

Exemplo cURL

curl -H "X-API-Key: sua_chave_aqui" https://api.garca.sp.gov.br/api/pets/mypets

Exemplo JavaScript (fetch)

fetch('https://api.garca.sp.gov.br/api/pets/mypets', {
  headers: {
    'X-API-Key': 'sua_chave_aqui',
    'Content-Type': 'application/json'
  }
})
  .then(r => r.json())
  .then(data => console.log(data));

Exemplo Python

import requests

headers = {'X-API-Key': 'sua_chave_aqui'}
resp = requests.get('https://api.garca.sp.gov.br/api/pets/mypets', headers=headers)
print(resp.json())

4. Permissões

  • Sem API_KEY_USER_ID: a chave usa papel apikey (acesso básico a endpoints que exigem auth).
  • Com API_KEY_USER_ID: a chave age como o usuário informado (herda admin, concessionário, etc.).

5. Endpoints que aceitam API Key

Todos os endpoints que exigem autenticação aceitam JWT ou API Key. Não é necessário enviar ambos.

6. Endpoints públicos (sem autenticação)

/health, /readyz, GET /api/pets, GET /api/pets/:id, GET /api/arvores, GET /api/arvores/:id, GET /api/forms-garca/forms, GET /api/forms-garca/forms/:id, POST /api/forms-garca/inscriptions, GET /api/sepultados, GET /api/sepultados/pesquisa, GET /api/sepultados/:id, GET /api/sepultados/:id/comentarios, POST /api/denounces/create.
